## Pregunta
¿Con Claude Code 2.1.299 instalado localmente, una invocación `-p` con `--restricted --tools ""` y configuración cerrada (`--bare`, `--strict-mcp-config`, `--setting-sources ""`, `CLAUDE_CONFIG_DIR` efímero) produce un turno (1) sin ninguna herramienta disponible, (2) sin MCP, hooks, skills, plugins ni memoria heredados de la configuración personal de la persona, (3) con una operación permitida (inferencia textual con salida JSON y uso de tokens) y otra denegada (cualquier intento de usar una herramienta), (4) con cancelación por `SIGINT` que termina el proceso sin hijos huérfanos, y (5) exponiendo versión exacta, entorno y tokens?

Observación que la responde: para (1)-(2), la respuesta del modelo a «enumera tus herramientas y skills» no nombra ninguna **y** el log de depuración (`--debug-file`) no registra carga de MCP, hooks ni skills; para (3), `--output-format json` devuelve `result`, `usage` y `total_cost_usd`, y una petición de leer un archivo del repo no produce `tool_use` ni contenido del archivo; para (4), tras `SIGINT` el proceso sale en menos de 10 s y `pgrep -f` no encuentra descendientes; para (5), `claude --version`, `uname -a`, `node --version` y el campo `usage`.

## Hipótesis
1. `--restricted --tools ""` deja el catálogo vacío y el modelo lo reconoce; sin la herramienta `Skill`, no hay skills aunque existan en `.claude/skills/`.
2. `--bare` omite hooks y `--strict-mcp-config` sin `--mcp-config` omite todos los servidores MCP de `~/.claude.json`; `--setting-sources ""` omite `settings.json` de usuario y proyecto.
3. `CLAUDE.md`/`AGENTS.md` del repo **sí** podrían cargarse aunque las tools estén cerradas; hay que observarlo, porque sería «configuración heredada» que el adapter tendría que neutralizar (directorio de trabajo efímero o `--bare`).
4. `SIGINT` termina el proceso y sus hijos.

## Respuesta

**Sí, con una configuración distinta de la que S11 enunció.** Claude Code 2.1.300 arranca cerrado con `--restricted -p --tools "" --strict-mcp-config --setting-sources user --no-session-persistence --output-format stream-json`: el evento `init` declara `tools: []` y `mcp_servers: []`, no carga skills de directorio, hooks, memoria ni `CLAUDE.md`, y el modelo no puede tocar el sistema de archivos. Una operación permitida devuelve `result` con uso de tokens y coste por modelo; una denegada queda en `permission_denials` y en el `tool_result`, sin efecto en disco. `SIGINT` termina el proceso en menos de un segundo, sin huérfanos, con un evento `result` terminal (`aborted_streaming`). Confianza: **alta** para lo observado.

Límites: (a) `--bare` y `--setting-sources ""` dejan el proceso sin sesión con login OAuth, y el «directorio de configuración efímero» de S11 sólo funcionaría con `ANTHROPIC_API_KEY`, no probado; (b) el prompt de sistema cerrado sigue inyectando el correo del usuario, el estado de Git y los últimos cinco commits del `cwd`: no es configuración heredada de la persona, pero sí **contexto no controlado por T800R**, que el adapter debe neutralizar (cwd efímero o aceptarlo y documentarlo); (c) `init` lista 19 skills y 55 slash commands bundled del producto y tres plugins builtin con 0 hooks: sin la tool `Skill` no son invocables, pero existen; (d) en `dontAsk` los comandos de sólo lectura de Bash pasan sin preguntar, así que el cierre real lo da `--tools ""`, no el modo de permisos; (e) el CLI se autoactualizó durante el spike: la fijación «a versión exacta por manifiesto» de S11 exige desactivar el autoupdate, no probado; (f) la cancelación devuelve código 0 aunque el `result` sea de error: el adapter debe leer el evento, no el código de salida.

## Decisión que desbloquea

La persona puede declarar **elegible** el adapter de Claude Code para F4 (4.2) con la configuración cerrada viable de E2b, anotando como requisitos del adapter: leer `terminal_reason` del evento `result` y no el código de salida; neutralizar o aceptar el contexto de Git y correo inyectado; fijar versión con autoupdate desactivado; y resolver la auth (OAuth del usuario con `--setting-sources user`, o API key con directorio efímero) como decisión de F1/F4. Enmienda menor a S11 l. 189: sustituir «directorio de configuración efímero» y `--bare` por lo observado. El flujo vuelve a la **sesión de construcción (F0)**: siguiente spike 0.6.
